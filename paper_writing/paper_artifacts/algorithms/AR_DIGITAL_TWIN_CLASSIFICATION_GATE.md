# Algorithm — AR–Digital-Twin Classification and Synchronization Gate

Input: candidate AR/MR + digital-twin study s
Output: D0-D6 maturity, evidence flags, allowed synthesis claims

1. Identify the physical asset/process.
2. Identify the digital representation and state variables.
3. Determine whether a physical-digital data link actually exists.
4. Determine directionality: none/manual, physical->digital, or bidirectional.
5. Record update mode: offline, event-driven, periodic, streaming/real-time.
6. If real-time/synchronized is claimed, extract update rate, latency, clock/alignment and state-consistency evidence.
7. Identify the AR/MR role: visualization, guidance, monitoring, collaboration, control, etc.
8. If digital->physical control exists, record control authority, confirmation, safety/failure handling and security constraints.
9. Record interoperability/protocol/data-model evidence.
10. Record lifecycle phase, intended users, environment and deployment duration.
11. Record technical, human and operational outcomes separately.
12. Assign D0-D6 using demonstrated evidence, not terminology used by authors.
13. A static BIM/CAD/3D overlay without live linkage cannot exceed D1.
14. One-way automated sensing cannot be called bidirectional.
15. A bidirectional prototype without sustained operational evidence cannot be called lifecycle/field twin.
16. QUALIFY or HOLD any claim whose synchronization evidence is absent.
